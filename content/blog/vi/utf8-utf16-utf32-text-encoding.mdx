## Mô Hình Unicode: Code Point vs Byte

Unicode ánh xạ các ký tự trừu tượng thành **code point** số (ví dụ: `U+0041` cho 'A', `U+1F600` cho '😀'). Định dạng chuyển đổi (UTF) quy định cách các số đó được tuần tự hóa thành byte nhị phân.

| Mã hóa | Byte mỗi ký tự | Tự đồng bộ? | Mức độ sử dụng Web |
|--------|----------------|-------------|---------------------|
| **UTF-8** | 1 đến 4 byte (Biến đổi) | Có | **98,2% tổng số website** |
| **UTF-16**| 2 hoặc 4 byte (Biến đổi) | Không (Cần BOM/Endianness) | Windows nội bộ / JVM / JS engine |
| **UTF-32**| Chính xác 4 byte (Cố định) | Có | Hiếm (tốn nhiều bộ nhớ) |

## Cách Hoạt Động Của UTF-8 Với Độ Dài Biến Đổi

- **Ký tự ASCII (0-127):** Mã hóa trong 1 byte (`0xxxxxxx`), duy trì 100% khả năng tương thích ngược với ASCII cũ.
- **Latin, Hy Lạp, Cyrillic (128-2047):** Mã hóa trong 2 byte.
- **Chữ Á Đông, CJK (2048-65535):** Mã hóa trong 3 byte.
- **Emoji & ký hiệu hiếm (65536+):** Mã hóa trong 4 byte.

```typescript
// Giải mã byte an toàn trong Node.js
import { TextDecoder } from 'util';

export function decodeTextSafely(buffer: Buffer): string {
  // fatal: true ném ngoại lệ thay vì chèn ký tự thay thế 
  const decoder = new TextDecoder('utf-8', { fatal: true });
  return decoder.decode(buffer);
}
```

## Byte Order Mark (BOM)
UTF-8 không yêu cầu Byte Order Mark vì các byte được sắp xếp giống nhau trên máy big-endian và little-endian. Tuy nhiên, một số phần mềm Windows (Notepad, Excel) thêm `0xEF 0xBB 0xBF` ở đầu. Luôn loại bỏ các byte BOM đầu khi phân tích tệp văn bản trong Node.js.
