Nhiều lập trình viên ngạc nhiên khi biết rằng một tệp Microsoft Word `.docx` không phải là tệp nhị phân độc quyền nguyên khối. Thực ra nó là một archive ZIP tiêu chuẩn chứa các tài liệu XML có thể đọc được, tài nguyên media và định nghĩa mối quan hệ tuân theo chuẩn Office Open XML (ECMA-376 / ISO 29500).

## Giải Nén Tệp DOCX

Vì DOCX là một container ZIP, bạn có thể đổi tên `document.docx` thành `document.zip` và giải nén bằng các tiện ích archive tiêu chuẩn:

```bash
unzip sample.docx -d extracted_doc/
tree extracted_doc/
```

```
extracted_doc/
├── [Content_Types].xml       <-- Ánh xạ các phần với MIME content type của chúng
├── _rels/
│   └── .rels                 <-- Mối quan hệ gói gốc
└── word/
    ├── document.xml          <-- Văn bản thực tế, đoạn văn và bảng biểu
    ├── fontTable.xml         <-- Khai báo font nhúng
    ├── settings.xml          <-- Tùy chọn view tài liệu và mức zoom
    ├── styles.xml            <-- Quy tắc định dạng đoạn văn và ký tự
    ├── media/                <-- Hình ảnh PNG, JPG, hoặc SVG nhúng
    └── _rels/
        └── document.xml.rels <-- Liên kết, hình ảnh và tham chiếu ngoài
```

## Kiểm Tra `word/document.xml`

Bên trong `word/document.xml`, nội dung được tổ chức thành đoạn văn (`<w:p>`) và run (`<w:r>`):

```xml
<w:p>
  <w:pPr>
    <w:pStyle w:val="Heading1"/>
  </w:pPr>
  <w:r>
    <w:t>Tóm Tắt Tài Chính Hàng Quý</w:t>
  </w:r>
</w:p>
```

## Tại Sao Điều Này Quan Trọng Với Lập Trình Viên
- **Chỉnh sửa lập trình nhanh:** Bạn có thể chỉnh sửa văn bản tài liệu hoặc thay thế biến mẫu bằng cách giải nén archive, thực thi regex hoặc thay thế DOM trên `word/document.xml`, rồi nén lại mà không cần cài Microsoft Word.
- **Phục hồi dữ liệu:** Nếu tệp DOCX bị hỏng, việc trích xuất `document.xml` thô thường phục hồi được 100% văn bản gốc.
