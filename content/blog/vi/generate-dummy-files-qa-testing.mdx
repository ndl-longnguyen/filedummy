## Tại Sao Dummy File Thực Sự Quan Trọng Trong Kiểm Thử QA

Sử dụng mock object trong bộ nhớ hoặc tệp placeholder zero-byte thường che giấu các edge case chỉ xuất hiện trên môi trường production:

- **Phân tích ranh giới multipart:** Web server và S3 proxy phải phân tích các marker ranh giới qua các buffer chunk.
- **Phát hiện MIME type và magic byte:** Tường lửa hiện đại và bộ xác thực tải lên kiểm tra 512 byte đầu tiên của tệp. Tệp zero-filled không vượt qua được phát hiện magic-number.
- **Dung lượng bộ nhớ và garbage collection:** Tải xuống tệp lớn truyền dữ liệu qua Node.js Buffer hoặc trình duyệt Blob. Nếu stream được xử lý sai, bộ nhớ tăng đột biến gây crash.

## Các Kịch Bản Kiểm Thử Tệp Phổ Biến Trong QA

### 1. Kiểm Thử Ranh Giới Kích Thước Tệp
Luôn kiểm thử cả giới hạn trên và dưới của quy tắc tải lên:
- **Tệp 0 byte:** Xác minh backend từ chối tệp rỗng nhẹ nhàng với HTTP 400 hoặc 422.
- **Đúng giới hạn (ví dụ 10MB):** Đảm bảo tệp có đúng 10.485.760 byte vượt qua xác thực.
- **Vượt giới hạn 1 byte:** Đảm bảo tệp 10.485.761 byte bị từ chối với HTTP 413 Payload Too Large trước khi toàn bộ upload được stream.

### 2. Xác Minh Định Dạng Tệp và Content-Type
Không bao giờ chỉ tin tưởng phần mở rộng tệp. Kiểm thử cách ứng dụng xử lý:
- Tệp PDF hợp lệ với header `%PDF-1.4` đúng.
- Đổi tên phần mở rộng (ví dụ: tệp `.exe` đổi tên thành `.pdf`).
- Header tệp bị hỏng và luồng tệp không đầy đủ.

```javascript
// Ví dụ: Xác thực kích thước tệp trước khi bắt đầu tải lên
function validateFileSize(file, maxSizeBytes = 10 * 1024 * 1024) {
  if (file.size === 0) {
    throw new Error("Tệp không thể rỗng");
  }
  if (file.size > maxSizeBytes) {
    throw new Error(`Tệp vượt quá kích thước tối đa cho phép ${maxSizeBytes / (1024 * 1024)}MB`);
  }
  return true;
}
```
