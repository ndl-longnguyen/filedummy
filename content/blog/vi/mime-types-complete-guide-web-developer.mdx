MIME types (Multipurpose Internet Mail Extensions), standardized by IANA, instruct web browsers and HTTP clients on how to interpret and render received byte streams. Setting incorrect MIME types results in files downloading as plain text, broken video streams, or security vulnerabilities like MIME-sniffing attacks.

## Common Web MIME Types Reference

| Extension | MIME Type | Description |
|-----------|-----------|-------------|
| `.pdf`     | `application/pdf` | Adobe PDF Document |
| `.docx`    | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | Microsoft Word |
| `.json`    | `application/json` | JavaScript Object Notation |
| `.csv`     | `text/csv` | Comma-Separated Values |
| `.zip`     | `application/zip` | ZIP Archive |
| `.png`     | `image/png` | Portable Network Graphics |
| `.jpg`     | `image/jpeg` | JPEG Image |
| `.txt`     | `text/plain` | Raw Plaintext |

## Enforcing Content-Type in HTTP Headers

```http
HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Disposition: inline; filename="statement.pdf"
X-Content-Type-Options: nosniff
```

## The Critical `X-Content-Type-Options: nosniff` Header
Older browsers attempted to "sniff" the content of a file regardless of what the `Content-Type` header declared. An attacker could upload an HTML file containing JavaScript disguised with a `text/plain` header; the browser would sniff the HTML tags and execute the malicious script (Cross-Site Scripting).

Setting `X-Content-Type-Options: nosniff` strictly commands the browser to trust the declared MIME type and refuse to execute non-executable files.
