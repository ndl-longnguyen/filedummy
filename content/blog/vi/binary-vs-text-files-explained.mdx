Ở cấp độ lưu trữ vật lý, tất cả tệp máy tính đều là chuỗi bit nhị phân (0 và 1). Tuy nhiên, hệ điều hành và ngôn ngữ lập trình phân biệt về cơ bản giữa tệp văn bản và tệp nhị phân.

## Điều Gì Phân Biệt Văn Bản Với Nhị Phân?

- **Tệp Văn Bản (.txt, .json, .csv, .html, .xml):** Chuỗi byte được diễn giải trực tiếp qua bảng mã ký tự (như UTF-8 hoặc ASCII). Các byte ánh xạ trực tiếp đến các glyph có thể in, ký tự xuống dòng (`\n`, `\r\n`) và khoảng trắng.
- **Tệp Nhị Phân (.pdf, .png, .docx, .zip, .exe):** Chuỗi byte đại diện cho dữ liệu máy có cấu trúc, lệnh đã biên dịch, luồng nén hoặc ma trận raster hình ảnh. Các giá trị byte tùy ý (từ `0x00` đến `0xFF`) xuất hiện xuyên suốt tệp.

## Kiểm Tra Null Byte (`0x00`)

Heuristic cổ điển được sử dụng bởi Git và các công cụ Unix như `file` để xác định liệu tệp có phải nhị phân là kiểm tra null byte (`0x00`) trong 8.000 byte đầu tiên:

```typescript
import fs from 'fs';

export function isBinaryFile(filePath: string): boolean {
  const buffer = Buffer.alloc(8000);
  const fd = fs.openSync(filePath, 'r');
  const bytesRead = fs.readSync(fd, buffer, 0, 8000, 0);
  fs.closeSync(fd);

  for (let i = 0; i < bytesRead; i++) {
    // Nếu tìm thấy null byte, gần chắc chắn là dữ liệu nhị phân
    if (buffer[i] === 0) {
      return true;
    }
  }

  return false;
}
```

## Xử Lý Chuyển Đổi Ký Tự Xuống Dòng
Tệp văn bản trải qua chuyển đổi carriage return / line feed giữa các hệ điều hành (`CRLF` trên Windows so với `LF` trên Linux/macOS). Cố đọc tệp nhị phân ở "chế độ văn bản" trong các runtime cũ có thể làm hỏng luồng nhị phân bằng cách thay đổi chuỗi `0x0D 0x0A`. Luôn mở tệp nhị phân với cờ nhị phân (`'rb'` hoặc `'binary'`).
