Khi xử lý các tài liệu cá nhân nhạy cảm, hồ sơ y tế hoặc mã nguồn độc quyền, mã hóa phía client zero-knowledge đảm bảo rằng tệp được mã hóa trong trình duyệt của người dùng trước khi truyền đi. Ngay cả khi cloud storage bị xâm phạm, dữ liệu được lưu trữ vẫn được mã hóa.

## Thiết Lập Mật Mã: AES-256-GCM

Chúng ta sử dụng **AES-GCM** (Galois/Counter Mode) qua **Web Crypto API** gốc của trình duyệt:
- Cung cấp mã hóa đối xứng 256-bit.
- Dữ liệu xác thực tích hợp (kiểm tra tính toàn vẹn) ngăn chặn giả mạo.
- Yêu cầu một Initialization Vector (IV) duy nhất cho mỗi lần mã hóa.

## Triển Khai Mã Hóa Phía Client Hoàn Chỉnh

```typescript
export interface EncryptedPayload {
  cipherBuffer: ArrayBuffer;
  iv: Uint8Array;
}

// 1. Tạo Khóa Mã Hóa AES-256
export async function generateAesKey(): Promise<CryptoKey> {
  return await crypto.subtle.generateKey(
    { name: 'AES-GCM', length: 256 },
    true, // có thể trích xuất
    ['encrypt', 'decrypt']
  );
}

// 2. Mã Hóa File ArrayBuffer
export async function encryptFile(file: File, key: CryptoKey): Promise<EncryptedPayload> {
  const iv = crypto.getRandomValues(new Uint8Array(12)); // IV 96-bit được khuyến nghị cho AES-GCM
  const plaintextBuffer = await file.arrayBuffer();

  const cipherBuffer = await crypto.subtle.encrypt(
    {
      name: 'AES-GCM',
      iv: iv,
    },
    key,
    plaintextBuffer
  );

  return { cipherBuffer, iv };
}

// 3. Giải Mã CipherBuffer
export async function decryptFile(
  cipherBuffer: ArrayBuffer,
  key: CryptoKey,
  iv: Uint8Array
): Promise<ArrayBuffer> {
  return await crypto.subtle.decrypt(
    {
      name: 'AES-GCM',
      iv: iv,
    },
    key,
    cipherBuffer
  );
}
```

## Các Lưu Ý Về Quản Lý Khóa
- **Dẫn xuất mật khẩu:** Không bao giờ dùng trực tiếp mật khẩu thô của người dùng làm khóa. Dẫn xuất khóa AES bằng **PBKDF2** với ít nhất 600.000 vòng lặp và salt duy nhất.
- **Lưu trữ IV:** IV 12-byte không phải là bí mật. Nối IV vào trước ciphertext được mã hóa trước khi truyền đến máy chủ.
